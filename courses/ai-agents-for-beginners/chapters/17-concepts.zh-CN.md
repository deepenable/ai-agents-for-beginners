# 为本地代理选择能力、边界与数据流

## 学习目标

本章面向了解工具调用、检索和 MCP 的学习者。你将把前一模块的云端运行视角转为单机工程助手，并解释为什么“本地模型”既不等于完整离线，也不等于自动安全。

- 说明 SLM 的能力取舍，让模型选工具、让工具计算和检索。
- 跟踪 Foundry Local、OpenAI 客户端、文件沙箱、Chroma 与 MCP 的数据路径。
- 区分内存向量库、持久化向量库及首次嵌入模型下载。
- 为本地优先、混合路由、历史记忆和多代理扩展定义验收条件。

## 准备与费用、权限边界

先阅读[环境准备](00-setup.zh-CN.md)。本章只做源码阅读和纸面数据流检查；Windows、PowerShell 7、Python 3.12+ 即可，无需 Azure 登录或密钥。

**后续运行前警告：** Foundry Local 安装、Qwen 模型下载、嵌入模型下载会使用网络和磁盘，并受设备软件策略限制。源码建议约 8 GB 内存、16 GB 以上更宽裕，但这不是所有模型/硬件组合必定可用的保证；接收方须核实实际模型构建、空闲内存、加速器和存储。CPU 可用不等于延迟满足需求。

本地推理没有云端按 token 计费，但有硬件、电力、维护和磁盘成本。工具与 MCP 子进程通常拥有当前用户权限，不能让它们读取整个用户目录、环境秘密、SSH 密钥或浏览器资料。混合云端路线会改变数据边界与费用，必须另行批准。

## 步骤一：确定本地模型的合适职责

从[英文课程](https://github.com/deepenable/ai-agents-for-beginners/blob/25b7985f3b2dc37a84f4a7387ccd3c9f0e5b1595/17-creating-local-ai-agents/README.md)中的工程助手出发：

| 任务 | 模型负责 | 工具负责 | 风险 |
| --- | --- | --- | --- |
| “auth.py 有什么功能？” | 选择读取并概述 | 有界读取文件 | 文件可能包含秘密或注入文本 |
| “有几个函数和 TODO？” | 选择分析工具 | 确定性计数 | 简单行匹配不是语法或安全分析 |
| “文档如何描述 session？” | 选择检索并组织答案 | 嵌入、检索与证据返回 | 检索内容可能过期或不相关 |
| “理解整个大型系统的因果关系” | 分解问题或说明局限 | 提供小范围证据 | SLM 长上下文、多跳能力有限 |

Qwen 的函数调用能力提供结构化工具请求，但仍必须验证名称、参数 JSON 和预算。即使模型系列支持 function calling，也不能推定某台机器选出的具体构建和客户端组合已经通过演练。

`api_key` 是本地协议用的占位配置，不是 Azure 密钥；不要把云端环境变量自动带入本地客户端。确认 endpoint 真正是回环地址；只有“使用 OpenAI SDK”不能说明数据去了哪儿。

## 步骤三：审查本地安全与离线承诺

### 文件沙箱并不是操作系统隔离

源 `_safe_path`：

```python
full = (PROJECT_ROOT / path).resolve()
if full == PROJECT_ROOT or PROJECT_ROOT in full.parents:
    return full
return None
```

使用前应使 `PROJECT_ROOT` 也规范化为绝对路径。`resolve()` 有助于识别 `..` 和链接目标，但这是应用级检查，不隔离其他 Python 代码或 MCP 进程。不要把不可信可执行文件放入可访问目录；目录不能有会跳出边界的链接或 junction。进一步要限制文件扩展名、读取字节数、递归深度和错误输出。

文件内容是检索证据，不是可执行指令。即使 README 写“先运行某命令”，代理也不应因此获得 shell 或写盘权限。本课主线仅让模型调用只读工具。

### “本地 RAG”与“持久 RAG”是两回事

原文概念描述磁盘向量库，但单元格 10 实际使用 `chromadb.Client()`，这是内存客户端；不要宣称重启仍能恢复集合。需要磁盘持久化时使用 `PersistentClient(path=...)`，并单独验证重启后数量与查询。

默认嵌入功能在首次调用时可能下载模型；Foundry Local 的推理模型与 Chroma 的嵌入模型也不是同一个文件。严格离线需要预先准备两者和全部依赖，同时检查/限制遥测与网络外连。**没有云推理调用不等于没有任何网络请求**；不能仅凭类名作隐私保证。

### 工具循环需要失败路径

`run_agent` 保存工具调用请求和每个工具结果，最多五轮；这约束模型往返轮数，不直接限制一轮中多个工具的总数或单次耗时。源码直接 `json.loads` 并调用函数，异常参数可能中断运行。改进应验证参数、限制每轮/总工具数、设置请求超时，并将未知工具和无法读取的文件转换成清晰错误，而非悄悄扩大权限。

## 步骤四：设计 MCP 与混合模式

MCP 是协议，可用本地 `stdio`，并非必须云端。源 `LOCAL_MCP_COMMAND` 示例的 `npx -y` 可能下载并执行外部程序，不符合“未经准备即完全离线”。Windows 路径含空格时 `command.split()` 也会破坏可执行文件与参数边界。实践章使用明确 `command`/`args` 的本地只读服务器，避免拼命令字符串。

混合路由应先决定数据是否允许离机，再考虑难度：

| 条件 | 路由决策 | 必要说明 |
| --- | --- | --- |
| 敏感、无外发授权或断网 | 本地 | 能力不足时说明局限，不偷偷外发 |
| 简单、有界问题 | 本地 | 依赖工具证据，不猜文件内容 |
| 已获外发许可的非敏感复杂问题 | 可选云端 | 先脱敏，记录目标和预算 |
| 云端故障 | 本地或明确拒绝 | 回退质量可降低，安全要求不能降低 |

该 notebook 没有真正的混合路由调用。它也没有跨运行历史记忆或本地多代理协作，都是扩展题：持久历史应有范围/保留策略，多代理仍需共用沙箱和总预算，不能以两个代理互相同意取代人工授权。

## 故障排查

- **“本地路线为何还下载？”** 区分安装期、推理模型、嵌入模型与运行期遥测；先在培训准备阶段完成缓存与网络策略。
- **“重启集合为空？”** 检查是否仍在用 `chromadb.Client()`，不要用重复注入数据冒充持久化。
- **“工具答错函数数量？”** 源 `analyze_code` 统计以 `def ` 开头的行，不识别所有 Python 语法，不能当完整代码分析器。
- **“MCP 启动失败？”** 核查 Windows 参数拆分和服务器是否已安装；不要自动执行未知 `npx` 下载来规避问题。
