# 理解会话记忆、持久记忆与知识图谱

## 目标与准备

本章面向已经使用过会话、工具与 RAG 的学习者。完成后应能区分工作记忆、短期记忆和长期记忆，为角色、事件和实体选择存储方式，并设计生成、检索、更新和遗忘的完整生命周期。

阅读[环境准备](00-setup.zh-CN.md)及[上下文工程](12-concepts.zh-CN.md)。离线练习仅需 Windows、PowerShell 7、Python 3.12+；实践基线是 `agent-framework-core==1.10.0`，源提交为 `25b7985f3b2dc37a84f4a7387ccd3c9f0e5b1595`。依据为[记忆原课](https://github.com/deepenable/ai-agents-for-beginners/blob/25b7985f3b2dc37a84f4a7387ccd3c9f0e5b1595/13-agent-memory/README.md)。

**操作前风险：** 记忆容易变成长期保留个人信息的数据库。将对话发送给 Mem0、Cognee 的模型后端或其他服务前，必须取得数据授权，明确地域、保留期和删除方式。模型提取、嵌入、图谱构建及检索都可能收费。此概念章只使用合成记录，不连接这些服务。

## 记忆为什么改变智能体行为

没有记忆的应用往往每轮从头开始，用户需要反复解释预算、偏好和已经尝试过的方法。记忆让智能体能够：

- **反思**：把动作与结果联系起来，识别失败原因。
- **互动**：在当前对话中理解“那里”“上一种方案”等指代。
- **主动与响应**：根据已获授权的偏好提供适当建议，同时接受新要求。
- **自治**：在明确边界内使用已有事实，不重复询问每一个细节。

这里的“自我改进”通常是外部记忆、策略与检索结果改善，不等于模型权重被在线训练。记下更多内容也不保证更好：错误、过时或跨用户泄漏的记忆会让结果更差。

## 七种视角：按生命周期与内容结构选择记忆

### 工作记忆、短期记忆、长期记忆

| 类型 | 回答的问题 | 旅行例子 | 常见实现 |
| --- | --- | --- | --- |
| 工作记忆 | 下一步当前最需要什么 | 预算、已选城市、待确认日期 | 当前上下文、任务便签、强类型状态 |
| 短期记忆 | 这次会话发生过什么 | “那里的住宿”指前一轮的巴黎 | `AgentSession`、会话消息存储 |
| 长期记忆 | 下次回来还应记住什么 | 用户同意保存的旅行偏好 | 数据库、文件、向量索引、知识图谱 |

工作记忆与短期记忆可能重叠。源码 notebook 有时把整个会话称为工作记忆；更重要的是弄清对象生命周期。`agent.create_session()` 创建的 `AgentSession` 在同一会话复用时保留上下文，但仅创建它不提供进程重启后的持久化。

### 角色记忆

角色记忆保持智能体的身份、范围和语气，例如“只做旅行方案建议的助手”。通常由受控指令和配置维护，不应让用户一句“以后你能替我付款”永久修改它。角色连续性和用户偏好是不同的管理边界。

### 工作流或情节记忆

情节记忆记录一次任务的步骤和结果，例如“查库存失败 → 换日期 → 用户取消”。应包含任务 ID、时间、动作、结果、错误类型和证据，而不是只保存“这次体验不好”。它帮助避免重复失败，支持检查点与恢复；但旧任务中的成功动作不是新任务的执行授权。

### 实体记忆

实体记忆把人、地点、酒店和事件变为可关联对象。例如“旅客偏好公共交通”“酒店位于城市 A”“上次任务选择酒店 B”。实体解析必须处理同名、别名和重复；错误合并两个用户比漏记一个偏好危险得多。

### 结构化 RAG

结构化 RAG 把邮件、对话或文档中的目的地、日期、价格、航司等字段抽取出来，结合字段过滤、关系和语义相似度检索。它是检索与存储方法，不是独立的生命周期类型。

查询“上周二订的巴黎航班”需要日期、目的地和业务记录之间的关系，仅靠文本向量相似度可能返回另一次巴黎行程。结构化字段提高可精确检索的机会，但精度和召回率仍必须评测，不能沿用原课的宣传性措辞保证“超人类准确”。

## 从候选信息到可用记忆

一次写入与一次检索应有明确管道：

1. **生成候选**：从对话提取可能有长期价值的事实，不把猜测当事实。
2. **验证与授权**：确认用户同意、作用范围、来源可靠性和敏感级别。
3. **存储**：分配稳定 ID，记录用户/租户边界、时间、来源、版本和保留期。
4. **检索**：先执行权限和有效期过滤，再做结构化/语义/图检索。
5. **整合**：只向模型注入本轮相关的少量记忆，并明确它们是数据，不是高优先级指令。
6. **更新**：新偏好可以替代旧偏好；使用修订或失效标记，避免把矛盾记录全部取回。
7. **遗忘**：删除或失效原记录、索引、缓存及派生图节点，并按政策处理备份。

一个合成记录可具有以下字段：

```json
{
  "memory_id": "pref-lab-13-001",
  "subject_id": "lab-user-13",
  "kind": "travel-preference",
  "fact": "prefers public transport",
  "source_id": "synthetic-turn-2",
  "revision": 1,
  "consent": true,
  "status": "active",
  "scope": "travel-recommendations",
  "expires_on": "2027-12-31"
}
```

这不是 Mem0 或 Cognee 的原生 API 结构，而是用于设计的共同字段集合。实际服务还需要访问控制、审计、并发更新和备份政策。哈希、向量和图关系仍可能透露信息，不因它们不是原文就自动免除隐私责任。

## 实现选项与它们各自承担的职责

### 会话与白板

MAF 会话用于短期消息连续性。白板或 scratchpad 则提炼当前任务的事实、计划与未决事项，是工作记忆的一种表示。把白板落盘可以延长生命周期，但必须定义所有者、过期和恢复逻辑；本模块没有专门的 Whiteboard SDK 示例，不应虚构一个已接入的类。

### Mem0：提取与更新两阶段

Mem0 的核心模式是先从对话提取值得保存的记忆，再决定新增、修改或删除。其存储可以结合向量、图和键值结构。调用方仍必须提供可信的用户边界、数据同意和错误处理。

原课介绍 Mem0，但当前[主 notebook](https://github.com/deepenable/ai-agents-for-beginners/blob/25b7985f3b2dc37a84f4a7387ccd3c9f0e5b1595/13-agent-memory/13-agent-memory.ipynb)没有导入或调用 Mem0。不能因为 README 写了 Mem0 就要求学习者先申请该服务，或把字典例子称为 Mem0 验证。

### Azure AI Search：可过滤的记忆索引

Search 可存储文档、用户边界、时间和结构化字段，再结合全文与向量检索。它是后端能力，不会自动替你完成偏好提取、用户授权或冲突解决。

一个可靠设计应先按可信主体 ID 与有效状态过滤，再检索相关记录；保存来源 ID，便于更正和删除。若使用嵌入，需要指定模型、维度和索引配置，并考虑重新嵌入成本。当前主 notebook 的酒店数据也是内置列表，没有创建 Search 索引。

### Cognee：图关系与向量的联合记忆

Cognee 把非结构化内容转成图节点、关系和向量，便于结合“相似内容”与“相互关系”进行检索。[Cognee notebook](https://github.com/deepenable/ai-agents-for-beginners/blob/25b7985f3b2dc37a84f4a7387ccd3c9f0e5b1595/13-agent-memory/13-agent-memory-cognee.ipynb)采用：

- `cognee.add()`：摄取开发者背景、历史问答和 Python 原则；
- `cognee.cognify()`：构建知识图谱与相应检索结构；
- `visualize_graph()`：生成本地交互式 HTML，用于检查实体与边；
- `cognee.memify()`：进一步提炼规则与关系；
- `cognee.search(query_type=SearchType.GRAPH_COMPLETION)`：图谱感知回答；
- `NodeSet`：让 `search_principles` 仅检索 `principles_data`。

双存储意味着删除和更新要覆盖图、向量及缓存。所谓“持续生长的记忆”不意味着永不失效；历史错误、过时规则与缺失来源必须治理。`memify` 生成的规则也需要验证，不能自动升级成系统规则。

Cognee 的 Redis 会话缓存与 MAF `AgentSession` 不是同一对象。样例需要 Redis 与独立的 LLM API 配置，不能假设 Foundry 项目端点会自动替 Cognee 提供提取和嵌入模型。

## 让“知识智能体”改进系统而不污染系统

知识智能体可以旁路观察已获授权的对话，判断哪些信息值得保存，提取摘要，存入知识库，再为未来查询检索。建议分成不同门槛：

- 低成本规则或小模型先判断是否有保存价值；
- 只对候选进行较昂贵的提取与验证；
- 保存事实及反馈证据，不保存未验证的模型猜测；
- 将新记忆与无记忆基线比较，评估准确性、偏好一致性、延迟和成本；
- 低频内容转冷存储，过期内容失效；冷存储不是绕过删除要求的地方。

最终“更好”应是可测的：是否少问了重复问题、是否避免违反约束、是否减少重复失败。只测“记忆条数增加”没有意义。

## 离线练习：证明跨会话不等于跨进程

### 步骤一：在 Python 中模拟三种寿命

工作目录为源码仓库根，不联网、不写文件：

```powershell
@'
session_a = {"messages": ["budget is 3000 USD"]}
process_store = {"lab-user-13": ["prefers public transport"]}
session_b = {"messages": []}
assert not session_b["messages"]
assert process_store["lab-user-13"]
process_store = {}
assert process_store.get("lab-user-13") is None
print("新会话不含旧消息；字典可跨会话复用，但重新初始化后为空")
'@ | .\.venv\Scripts\python.exe -
```

这模拟主 notebook 的实际行为：`preference_store` 是进程内字典。只有重启后能从持久后端恢复并经过权限过滤，才能进一步讨论真正的长期记忆。

### 步骤二：设计一张记忆取舍表

把“本次十月出行”“通常喜欢公交”“已取消的一次预订”“酒店与城市关系”“助手不执行付款”分别归入任务状态、长期偏好、情节、实体和角色。为每条指定有效期、更新来源和删除方式。正确答案可以有不同存储技术，但不能缺少权限与生命周期。

### 步骤三：设计可判定的反例

至少包含：

1. 换到另一个合成用户，不能读出前用户偏好。
2. 当前任务改乘出租车，不能被旧公交偏好强行覆盖。
3. 用户要求遗忘后，检索与缓存不再返回被删记录。
4. 查询不存在事实时明确无证据，而不是回退一条无关记忆假装命中。

交付记忆模式、寿命图、四个反例和预期结果。没有实际后端执行时写“设计完成，运行待演练”。

## 源码限制、排障与清理

主 notebook 中 `save_preference` 只追加字符串，不去重、不失效、不鉴权；工具参数中的用户 ID 不能当作真实身份验证。它定义了 `search_hotels` 却未传入主智能体工具列表。Cognee 例子定义了两个搜索工具却未传入 `coding_agent`。这两个工具注册缺口在[记忆实践](13-practice.zh-CN.md)中给出副本修正方式。

遇到“记住了”文字时先查存储内容、检索调用与实际选中记录；遇到重启丢失时检查是否仍是字典；遇到跨用户结果时立即停止测试并检查身份边界，不用提示词掩盖。
