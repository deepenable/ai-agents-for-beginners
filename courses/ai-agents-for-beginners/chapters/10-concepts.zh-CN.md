# 生产可观测性与评估：把行为变成证据

## 学习目标与准备

本章关注上线前必须回答的问题：智能体做了什么、哪里慢或贵、结果是否正确、修改后有没有退化。完成后，你应能区分 trace、span、指标与评估，设计离线—在线改进闭环，解释小模型、路由和缓存的成本取舍。

先掌握[可信智能体](06-concepts.zh-CN.md)与[响应反思](09-concepts.zh-CN.md)。概念活动无需生产账号或云资源；实践使用[准备章](00-setup.zh-CN.md)的 Windows PowerShell 7、Python 3.12+、`agent-framework-core==1.10.0`。依据为[第 10 模块原文](https://github.com/deepenable/ai-agents-for-beginners/blob/25b7985f3b2dc37a84f4a7387ccd3c9f0e5b1595/10-ai-agents-production/README.md)。本章教授生产思路，不要求部署或测试生产流量。

## 从黑盒到可解释的运行记录

一次回答可能包含多次模型调用、检索、工具、条件分支和人工审批。只保存最终文本，无法判断错误来自模型、工具数据、路由还是执行层。可观测性不是读取模型的内部思维，而是记录系统可见的执行事实。

- **Trace**：一次完整任务的关联链，例如一次巴黎旅行咨询。
- **Span**：链中的一个操作区间，例如一次模型请求、航班工具调用或审核。
- **日志**：具体事件与错误细节，用关联 ID 连接到任务。
- **指标**：跨任务聚合的延迟、错误率、调用量、token 和质量信号。

可以将旅行咨询表示为以下示意结构，它不是本次实际采集结果：

```text
travel_request
  model_select_tools
  get_flight_info
  get_activity_suggestions
  model_compose_answer
  evaluate_answer
```

多智能体还需要记录角色和交接边。最终摘要正确不代表中间没有越权；中间工具成功也不代表用户目标完成。

## 为什么生产环境更需要可观测性

### 调试与根因分析

工具返回空值、JSON 解析失败、角色丢失预算和模型编造信息，可能都表现为“答案不对”。关联 trace 可以沿实际路径定位首个异常，避免通过不断加提示来掩盖坏数据。

### 延迟与费用

总耗时由模型、网络、工具和排队组成。应该先找瓶颈，再考虑更快模型、并行独立请求或缓存。总耗时不是所有 span 耗时的简单相加，并行操作会重叠。单次计时不能说明稳定性能，应在可控数据集上统计分布，并区分冷启动和正常运行。

### 信任、安全与合规

审计证据应说明动作来源、权限、批准和结果，以调查提示注入、不当工具使用或个人信息处理。日志本身也是敏感数据面：完整提示、收据、用户标识和模型回复都可能泄露信息。默认最小化、脱敏、限制访问和保留期，不能为了排障把秘密发送到第三方平台。

### 持续改进

将真实失败模式转成去敏离线用例，修复后再验证，是可观测性的长期价值。仅展示一个仪表盘不会自动改进系统；必须明确谁处理告警、什么条件阻止发布、怎样回退。

## 应跟踪哪些指标

| 信号 | 需要回答的问题 | 常见误读 |
| --- | --- | --- |
| 端到端与步骤延迟 | 用户等待多久，哪个环节最慢 | 一次快响应不代表所有请求都快 |
| token、调用数与费用 | 一次任务及重试花费多少 | 只数最终回答 token，漏掉工具和评估请求 |
| 请求与工具错误 | 哪些依赖常失败，是否重复调用 | 返回 HTTP 成功就认为任务成功 |
| 明确用户反馈 | 用户为什么点赞、差评或投诉 | 满意度等同事实正确 |
| 隐式反馈 | 是否反复改写问题、重试或放弃 | 点击就是认可，或重复就一定错误 |
| 准确性与任务完成 | 输出是否满足预先定义的成功标准 | 没有标准答案也声称准确率 |
| 自动评估分数 | 是否完整、相关、可用、存在风险 | LLM 高分可以取代人工与确定性校验 |

离线真值、人工抽样、模型评估与用户反馈应结合使用。原文提到 RAGAS 可评估检索增强任务、LLM Guard 可帮助检测不当内容与注入；这些是工具类别参考，不是本模块 notebook 已安装和启用的能力。

## 埋点与 OpenTelemetry

OpenTelemetry 提供生成、收集和导出遥测的标准接口。MAF 的 observability 模块提供 `get_tracer`、`get_meter` 等入口；自动埋点覆盖框架操作，手工 span 可补充业务步骤和必要属性。

源原文的最小示意是：

```python
from agent_framework.observability import get_tracer, get_meter

tracer = get_tracer()
meter = get_meter()
with tracer.start_as_current_span("agent_run"):
    pass
```

这段没有真实 agent 调用，也没有配置 exporter。出现 context manager 不意味着数据已送到 Foundry、Langfuse 或其他平台；需要额外的采集配置、访问授权、脱敏和保留策略。原文的 Langfuse 手工 `start_span`/`end` 展示另一种记录方式，但本课程不要求开设或连接该服务。

手工属性宜记录无敏感业务类别、版本或合成用例 ID。不要默认把真实 `user_id`、完整消息、身份证、收据图像或令牌写入 span。异步与多分支需保持关联上下文，否则会得到互不关联的事件碎片。

## 评估是作判断，而不只是采数据

可观测性提供发生了什么；评估回答好不好、为什么、能不能发布。由于模型非确定性和环境漂移，评估应持续进行，而不是只在首个成功演示后停止。

### 离线评估

在受控数据集上运行已知问题和预期行为，不接受实时用户请求。数据可包含正常场景、无资料、模糊输入、工具异常、越权请求和边界格式。

“离线评估”不等于“不联网”：数据集是离线的，调用云模型评分仍可能计费。优点是可重复对比、容易查回归；缺点是数据分布可能与真实使用不同。用小型冒烟集合快速检查基本行为，再用更广集合衡量质量，定期加入新失败案例。

### 在线评估

在真实使用中跟踪任务成功、反馈、漂移和未预料场景。影子运行可以让新版本旁路观察但不影响用户；A/B 测试比较不同版本。两者都需数据与实验授权、成本控制和明确安全边界，本课程只讨论，不实施。

在线标签往往不完整，用户行为也可能受界面或网络影响。不能将所有差评都归因于模型，更不能未经去敏就把生产对话复制到训练或实验数据。

### 形成闭环与放行门槛

可用“离线评估 → 批准发布 → 在线观察 → 去敏失败样本 → 修复 → 再评估”的循环。每轮定义质量、延迟、成本与安全门槛；任何关键项失败都应停止或回退，而不是用整体平均高分遮蔽严重错误。

例如报销任务至少需要项目数完整、金额核对、币种正确、未重复计入总计、没有真实发送邮件。语言流畅只是次要标准。评估模型不知道真值时，最多检查内部一致性，不能独立证明 OCR 正确。

## 常见生产问题与处理顺序

- **任务执行不一致**：先检查输入契约和成功标准，再改进提示；职责确实不同才拆为多智能体。
- **连续循环**：设置明确结束条件、最大请求和预算。推理模型可能改善规划，但不能代替强制上限。
- **工具调用不好**：在智能体外先测试工具数据、参数和错误，再改描述与命名；不要用模型重试掩盖工具缺陷。
- **多智能体失去协调**：检查角色是否重叠、消息是否丢约束，必要时用明确路由或层级控制者。

这些问题需要从 trace 和工具契约定位；“换更大模型”不是所有问题的恢复方案。

## 成本管理要以评估为前提

1. **小模型处理简单任务**：分类、字段提取可以考虑较小模型，复杂推理用更强模型；先对同一数据集测质量，不能仅按单价决定。
2. **模型路由**：用规则、小模型或函数识别复杂度，再决定模型。路由器本身有费用、误判和延迟，应计算端到端收益。
3. **缓存**：复用稳定工具结果与常见回答可减少调用；必须区分用户权限、数据版本、失效时间和个性化内容，防止跨用户泄露或返回旧房态。
4. **提示与输出预算**：减少冗余上下文、限制不必要长回答和重复反思。不同 API 参数名不同，不能把原文 `max_tokens` 直接复制到所有客户端。
5. **批处理与并发**：适合独立任务，但须兼顾每项归属、错误隔离、配额和重试。并发缩短等待不代表费用下降。

总成本包含输入/输出 token、工具服务、评估、重试、存储与遥测。价格随部署变化，本手册不虚构实际费用。

## 动手活动：设计一张旅行评估卡

不运行模型，选择“巴黎一日游：航班与活动建议”作为合成用例：

1. 写出两个必需产物：航班信息和活动建议；写出不允许发生的动作：真实预订或支付。
2. 设计 trace，标出工具、模型与评估阶段，不把所有耗时混在一个数字里。
3. 定义确定性检查，例如“包含工具提供的航班信息、不添加不存在的价格”；另定义需人工判断的可行性。
4. 给无资料城市、工具异常和答案遗漏分别写预期行为。
5. 提出一个降本方案和它的回归风险，例如缓存可能过时；指定复验用例。

预期产物是可操作的评估卡，不是“准确、快速、便宜”三个形容词。若评分没有真值，补充原始工具数据；若只记录均值，补充尾部延迟与错误；若日志含身份，先脱敏再保存。

## 风险、清理与演练状态

概念活动不创建云资源。真实云评估会付费；遥测与收据上传可能涉及隐私和跨系统数据传输，必须事先授权。不得将本课程的简单示例直接作为财务放行或生产上线门禁。
