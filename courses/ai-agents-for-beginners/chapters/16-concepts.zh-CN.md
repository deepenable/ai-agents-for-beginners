# 把代理能力转化为可运营的服务

## 学习目标

本章面向已做过工具调用、RAG、记忆和评估练习的学习者。完成后，你应能解释部署模式的差别，画清发布关卡与运行时责任，并识别“源码演示了模式”与“已具备生产实现”之间的距离。

- 比较客户端托管、服务托管和工作流编排。
- 把版本、离线评估、发布、线上观察和退役连接成生命周期。
- 分析模型路由、缓存、状态、并发、人工审批和可观测性之间的依赖。
- 为 Contoso 支持代理提出可测的改进项，而非只增加一个更大的模型。

## 准备与费用、权限警告

先阅读[环境准备](00-setup.zh-CN.md)。本章使用 Windows、PowerShell 7、Python 3.12+ 阅读源文件，不需要云凭据或部署权限。[实操](16-practice.zh-CN.md)主线可以只用标准库验证本地规则。

**执行任何云端变体之前**，由接收方提供培训 Foundry 项目、实际模型部署、最小权限身份和预算。模型请求、Search、日志存储及独立托管运行时可能分别计费。不要在共享订阅创建或删除资源，不要给代理订阅级管理员权限。模拟退款不是支付授权；接入真实退款、工单或取消订阅工具属于新的有副作用任务。

本章依据[英文课程](https://github.com/deepenable/ai-agents-for-beginners/blob/25b7985f3b2dc37a84f4a7387ccd3c9f0e5b1595/16-deploying-scalable-agents/README.md)及[真实笔记本](https://github.com/deepenable/ai-agents-for-beginners/blob/25b7985f3b2dc37a84f4a7387ccd3c9f0e5b1595/16-deploying-scalable-agents/code_samples/16-python-agent-framework.ipynb)。单元格编号是零基 `cells` 数组下标，不是执行计数。

## 步骤一：划清运行位置与责任

| 模式 | 运行与状态责任 | 适用场景 | 不能省略的工作 |
| --- | --- | --- | --- |
| 客户端托管 | 应用管理请求循环、本地工具和应用状态 | 嵌入已有后端，需定制中间件 | 扩缩容、状态外置、重试、身份、监控 |
| Foundry 托管运行时 | 已部署的服务负责其支持的代理运行能力 | 需要可运营端点及托管治理 | 打包/部署、依赖与工具连接、端点验收 |
| 代理工作流 | 显式图管理分支、多个代理、审批和恢复点 | 业务跨多个步骤或需要暂停恢复 | 持久化、幂等性、编排级追踪与补偿 |

资源注册和代码托管不是同一件事。源码单元格 13 的 `client.as_agent(name="ContosoSupportAgent", ...)` 使用 Foundry 客户端并可能形成服务器端代理资源，但本地 Python 工具、缓存、客户字典和请求处理函数仍在 notebook 进程。单元格 18 的 `release` **只是再次评估并打印晋级提示**，没有部署、打包、滚动发布或扩容 API。

因此，本实验不能把打印 `Gate passed`、门户里看到代理，或客户端成功回答一次问题，写成“已部署持续运行的 Hosted Agent”。云端 smoke test 要求另有一个已经部署、可服务请求的 endpoint。

## 步骤二：把发布生命周期写成关卡

按照“创建 → 固定版本 → 离线评估 → 批准发布 → 线上观察 → 失败回流 → 改进/退役”检查一个变更：

1. 固定模型部署名、提示词、工具模式、知识库版本和依赖，不只固定 notebook。
2. 在代表性用例上评估，拒绝不满足质量与安全门槛的版本。
3. 晋级后进行 endpoint 冒烟检查，发现身份、模型连接、工具依赖或线程问题。
4. 用脱敏追踪定位线上失败，将其加入回归集。
5. 退役旧版本前处理活跃会话、数据保留和回滚窗口。

源 `TEST_CASES` 只有退货、配送、订单和保修四例。单元格 16 的每例通过标准是关键词比例 `>= 0.5`，整个关卡是 `>= 0.8`。四例中三例通过只有 75%，因此默认门槛实际上要求四例都通过。这不是 README 示意代码中的单例 80%。

“离线评估”指使用预先准备的数据集，不一定指断网。原始 `evaluation_gate` 调用 `support_agent.run`，会访问模型并计费；本地规则演练使用假的响应对象替代它，不能宣称测了模型质量。

## 步骤三：逐项审查生产控制

### 工具、检索与记忆

单元格 5 的 `ORDERS`、`TICKETS` 是内存模拟。`get_order_status` 查订单，`open_ticket` 向列表追加，`issue_refund` 只返回字符串。单元格 7 的 `search_policies` 在配置齐备时用 Search，否则执行 `_in_memory_search`；后者是关键词匹配，不是向量搜索。

单元格 9 的 `CUSTOMER_MEMORY` 只是两个虚构客户档案，`memory_context` 把摘要拼入提示。它不是跨进程持久会话服务，也不是自动从每次对话学习出的长期记忆。要水平扩容，应将必要状态外置，并规定访问控制、版本与保留期限。

### 路由、缓存、并发与成本

单元格 11 的 `is_simple` 检查 `refund/cancel/complaint/escalate/broken/wrong/why` 等英文词及 20 词长度。它不能自动理解所有语言的风险，也不是 Foundry Model Router。单元格 13 为每个模型建立独立客户端，`agent_for` 才是真正的模型选择入口。

关键源码：

```python
key = normalize(query)
if key in response_cache:
    route_counters["cache"] += 1
    return response_cache[key]
```

这个键没有客户、授权范围、会话或知识库版本。两个客户问相同的“我的订单到哪里了”，可能拿到相同缓存答案；模拟也不应把它当作可上线方案。对于工具写操作不缓存，对客户相关回答至少隔离客户和权限上下文；公开 FAQ 还需要版本和过期策略。

`SMALL_MODEL` 与 `LARGE_MODEL` 都可回退到同一个默认部署。这便于跑通，但会让实际模型没有差异，并使按模型名计数的逻辑把全部未命中请求记成 small。不能据此计算节省比例。

源码没有实现并发上限、429 退避或幂等性。补充设计至少包括：有界信号量、整体超时、有限重试、写工具幂等键和队列背压。重试退款与重试只读查询不能使用相同策略。

成本估计应由实际模型用量乘接收方提供的当期输入/输出价格，再加工具、Search、日志和运行时成本；`route_counters` 只统计分流次数，不是账单。先找能通过评估的小模型，再路由和缓存，不以降低质量换“便宜”。

### 人工审批与遥测

`refund_needs_approval` 表达金额大于 50 的规则，但没有接入 `issue_refund` 的装饰器分支。装饰器是 `@tool(approval_mode="always_require")`，意为该工具每次都需要批准，不是自动只拦截大额。源请求处理器只返回 `response.text`，没有完整展示批准请求的解析、人工界面及恢复执行；不能把有装饰器等同于完整 HITL 流程。

`get_tracer()` 或 `_NoopTracer` 包围请求，附加 `customer.id`、`routed.model`。空操作 tracer 不会产生实际追踪；有 span 也不等于已配置导出器和 Foundry 连接。缓存命中在 span 之前返回，单凭这个 span 看不到命中路径。生产应记录命中/未命中、延迟、错误、工具耗时与令牌用量，避免记录真实客户标识和完整提示。

MCP 作为生产工具边界还应固定服务器版本、验证输出、最小权限、限流和超时。这个 notebook 没有实际 MCP 集成；不能把概念清单标为已实现。

## 步骤四：区分三层验证

| 层次 | 问题 | 本源码入口 | 不能证明 |
| --- | --- | --- | --- |
| 离线评估集 | 已知任务是否达到门槛 | 单元格 16 `evaluation_gate` | 部署 endpoint 可达 |
| 发布后 smoke test | 端点是否回复基本预期 | `tests/lesson-16-smoke-tests.json` | 完整质量、安全或退款执行正确 |
| 线上观测/评估 | 真实负载哪里失败 | 请求 span 与后续遥测方案 | 未采集事件的表现 |

冒烟目录有六项，包括 30 天退货、A1001、3–5 个工作日配送、不要跑题和两轮 A1002 记忆。`contains_any` 是子串匹配，例如回复里仅出现订单号也可能通过订单项；不包含两句海盗诗也不保证真正拒绝离题请求。应在教学报告里解释这些弱断言，而不是把它们当完备安全测试。

## 预期结果

写出一张差距表，至少标出：没有真实 hosted 部署、没有持久会话、缓存不隔离客户、审批恢复路径未实现、遥测可能为空、评估覆盖不足。每项给出一个验证方法和失败时的阻止发布条件。

合格设计应能回答：缓存能否跨客户共享？默认两个模型相同会怎样？为什么 3/4 不过关？发布提示为何不能作为端点证据？大于 50 的辅助函数与始终审批装饰器有什么区别？

## 故障排查

- **找不到部署结果**：查看 `release` 函数体；该样例确实没有实际部署步骤，不能靠反复执行补出运行时。
- **没有追踪数据**：区分空 tracer、未导出与缓存提前返回，逐层定位，不直接开启全量敏感日志。
- **低成本报告异常漂亮**：检查两个模型名是否相同、是否把计数当成实际 token 消耗。
- **评估通过但回答不对**：核查关键词弱匹配和测试覆盖，不仅提高通过率阈值。
